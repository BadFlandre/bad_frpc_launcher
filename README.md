# Bad frpc Launcher ✨

一个给 `frpc` 准备的可视化小启动器，目标很单纯:

- 让你不用每次都手搓命令行
- 让 `frpc.toml` 可以直接在界面里改
- 让日志乖乖待在窗口里，不要到处乱飞

## 项目简介 🌸

`Bad frpc Launcher` 是一个基于 Rust + `eframe/egui` 编写的 Windows 桌面启动器。

它主要负责这些事情:

- 编辑和保存 `frpc.toml`
- 启动、停止、重启 `frpc.exe`
- 实时读取 `stdout/stderr` 日志
- 把日志保存到本地文件
- 提供简单配置模式和高级配置模式

适合不想一直开着终端、又想更直观管理 `frpc` 的场景。

## 功能亮点 💡

### 1. 简单配置模式 🧁

比较适合日常使用，直接填写常见项目:

- 服务器地址
- 服务器端口
- Token
- 映射名称
- 协议类型 `TCP / UDP`
- 本地 IP / 本地端口 / 远端端口

写完就能生成对应的 TOML，省一点点心力，少一点点手误。很乖。

### 2. 高级配置模式 🛠️

如果你更喜欢自己直接写配置，也没问题。

- 支持直接编辑完整 `frpc.toml`
- 会做基础 TOML 语法检查
- 保存前能看到语法是否正常

也就是说，你既可以当它是“可视化表单”，也可以当它是“带一点照顾的配置编辑器”。

### 3. 进程控制 ▶️

界面内直接操作 `frpc`:

- 启动
- 停止
- 重启

而且会轮询进程状态，尽量让“运行中 / 已停止”显示得更明确，不至于像失联一样让人心慌。

### 4. 实时日志 📜

启动器会把 `frpc` 的输出读进界面里:

- 标准输出 `stdout`
- 错误输出 `stderr`
- 启动器自身的错误提示

日志支持滚动查看，也支持保存到文件，排查问题时会更方便一点。

## 技术栈 🧪

- Rust 2021
- `eframe`

## 项目结构 📁

```text
bad_frpc_launcher/
├─ Cargo.toml
├─ main.rs
└─ frpc/
   ├─ frpc.exe  # frpc可执行文件
   ├─ frpc.toml  # frpc配置文件
   └─ frpc.toml.example  # 示例配置文件
```

默认情况下，程序会尝试使用下面这些路径:

- `./frpc/frpc.exe`
- `./frpc/frpc.toml`

所以只要目录结构别乱跑，一般都能顺顺利利找到目标文件。

## 快速开始 🚀

### 1. 准备环境 🧰

你需要:

- Windows
- Rust 工具链
- 可用的 `frpc.exe`

如果项目目录下已经放好了 `frpc/frpc.exe`，那就更省事了。

### 2. 运行项目 ▶️

在项目根目录执行:

```bash
cargo run
```

### 3. 构建发布版本 📦

```bash
cargo build --release
```

构建产物通常会出现在:

```text
target/release/
```

## 使用说明 🫶

### 配置文件 ⚙️

程序启动后会尝试读取 `frpc.toml`。

- 你可以在“简单配置”里用表单方式编辑
- 也可以切到“高级配置”直接改 TOML
- 如果有未保存内容，启动 `frpc` 前会优先尝试保存

### 日志保存 📝

日志页可以:

- 查看实时日志
- 清空当前界面缓存
- 保存当前缓存到本地文件

默认日志文件名是:

```text
bad_frpc_launcher.log
```

### 运行逻辑 🧠

启动 `frpc` 时，大致相当于执行:

```bash
frpc.exe -c frpc.toml
```

只是这些事情会被 GUI 包装起来，显得没那么冷冰冰而已。

## 注意事项 ⚠️

- `frpc.toml` 里可能包含 `token` 等敏感信息，不建议随便提交到仓库 🔐
- 停止功能在 Windows 下本质上是强制结束进程，不是温柔劝退型 💥
- 当前主要面向本地自用场景，功能重点是“够直接、够省事” 🍵
- 如果路径被改得太离谱，请在界面顶部手动指定 `frpc.exe` 和配置文件路径 🧭
